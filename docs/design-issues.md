# 混合 EPaxos：哪些事情还需要研究者决定

本文件对应 2026-11-06 的两份混合 EPaxos PDF，不再描述旧 Fast/Seal 协议。它供研究者讨论，不作为 agent 的额外要求。当前规范在 [protocol.md](../inputs/protocol.md)，操作细节在 [pseudocode.md](../inputs/pseudocode.md)。这里不把缺少完整证明当作已经发现错误，也不把能自行选择的工程方案变成人工审批事项。

## 1. 已确定：本轮先限制为 10,000 条新逻辑请求

每次从干净状态启动的集群，所有客户端合计最多提交 10,000 条新逻辑请求，以不同 rid 计数。相同 rid、相同载荷的重试不占新的请求额度，但可能产生新的协议实例，因此分别记录逻辑请求、重试和实例数量。这个上限不限制整个 agent 会话能运行多少个独立测试，也不要求每个测试跑满一万条。

上限由测试或负载程序控制。达到后停止提交新的逻辑请求，继续在执行预算内处理重试、恢复和执行；预算用完时如实记录未完成工作。共识服务不因此硬编码“一万条后永久拒绝”，也不丢弃已接纳请求或删除必要历史。

每次集群运行选定一个固定 W。历史增长可能增加实际扫描、传输和验证耗时，但协议的 W 不会自动随之变化。一万条的数量限制本身不证明窗口前提成立，仍需结合实际事件观察。具体 W、负载分布和实现优化可以由 agent 选择并说明；不需要现在引入动态窗口或垃圾回收。

本轮暂不讨论长期无限运行的资源保证，只在实际满足 W/s 前提的有限工作负载下实现和检验协议。将来若扩展长期服务范围，再讨论历史回收、时间模型或负载前提；该议题不阻塞当前实验。

## 2. 尚未完成的证明，不是实现时可以任选答案的地方

原文明确保留了以下论证义务。这些不是要求生成 agent 停下来等人工选择，也不是已经证实的协议缺陷。

| 论证 | 还需要确认什么 | agent 不能靠什么替代 |
| --- | --- | --- |
| Cover、Selection 和 NoFast 的完整有效性 | 追溯继承和跨实例证据时，每一步确实支持允许的选值，最终满足 Agreement 与冲突可见性 | 只检查“有证书”或把验证函数写成恒真 |
| HELP 与并发 ballot 的组合 | 多任务抢占、双向帮助、冻结前后到达的证据，是否总能保持安全并最终推进 | 删掉 HELP、偷偷改 quorum、用 Nop 释放槽或永久搁置难例 |
| Omega 与恢复的整体终止性 | 心跳与投诉构造在给定时序前提下稳定后，恢复和证据取回能否使所需实例完成 | 用永远正确的 leader oracle 替代实际 Omega，或按超时准确判死 |
| 客户端历史的条件性结论 | Agreement、Visibility、有限闭包、返回值可交换性和去重都满足时，具体服务是否保持相应历史语义 | 仅凭执行后回复或几次最终 KV 相同就宣称已证明线性一致性 |

若审计得到忠实实现也会发生的合法反例，需要回到协议设计，而不是让修复 agent 私自选择一个新协议。应保留反例、依赖的规则和现有证据，区分规格反例与实现偏离；现有问题报告、规格问题说明和独立复核足以承接，不增加自动判定模块或新门禁。

## 3. 这些已经明确，不需要再次决定

- crash-stop 表示副本永久退出，没有暂停后恢复、重启、追赶或丢失内存后重新加入；不因此要求 WAL。
- W 从广播开始计时；不是广播完成后才开始，也不是所有消息都在 W 内到达。窗口允许 s 个仍存活成员尚未回复，慢成员可随窗口变化。
- Collect 使用 q/L 的两阶段规则；Fast 使用 F。窗口到期而响应不足 q 时继续等，第二阶段不另等 W。
- 正常原主遇到 Mismatch 可以选择正常异值 Accept，不要求 NoFast；正 ballot 无继承的重建需要 NoFast。最高 accepted 的继承优先级不能被 HELP 改掉。
- 执行后释放原主的槽，但实例仍参加未来冲突扫描；不做本地剪枝和安全回收。
- 重试保留 rid 与载荷，允许新入口分配不同实例；应用状态与请求结果表一起去重。实例执行一次与逻辑请求效果一次是两层要求。
- 完整稿不存在 §9.4 是交叉引用笔误。材料整理已使用伪代码稿 §13.4 的实际验证边界，没有把笔误升级为协议选择。

## 4. 这些可以交给实现 agent 自行决定

包划分、接口命名、单事件循环或其他同步方式、队列组织、消息编码、索引、物理对象共享、不可变对象验证缓存、请求号的具体编码、客户端等待与退避、恢复通知宽限、后台重试间隔、测试接口和测试内容，都可以由 agent 分析选择并说明。选择要保持共同材料规定的状态转换、窗口和公平性前提，不要求某种预先指定的数据结构。

例如，客户端超时设为多少、一次同时联系几个入口，可以是实现策略；超时后换 rid 重做同一逻辑操作则改变了请求语义。怎样表达证据引用可以自行决定；把缺证据当作 NONE 或跳过 Accept 前的验证则违反已明确规则。观测点放在哪里可以设计；不能把“实际收到响应”的窗口前提悄悄改成“对端收到请求”。

当前尚未发现必须由研究者二选一、否则连协议路径都无法确定的新增文本冲突。可以按现有材料和已确定的一万条请求范围生成、检验实现；第 2 项保留为后续论证与反例研究，不要求生成 agent 先完成证明。
