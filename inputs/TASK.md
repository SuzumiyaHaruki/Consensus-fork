# Implement the supplied consensus system

Read protocol.md and system.md in full and deliver the complete runnable system they describe. Follow IMPLEMENTATION.md for shared practices. Deliver programs, reusable components, tests and documentation; a plan or library alone is insufficient.

## Build and investigate

Start DESIGN.md with a short sketch and update it alongside the code. Build in runnable increments: take one request through client entry, replica communication, decision, application execution and response, then extend the same implementation to the required concurrency, faults and lifecycle behavior. This order does not reduce final scope. Check interactions as features are added and review code organization before delivery.

Prioritize demonstrated failures and unexplained runtime behavior over more similar passing tests or report polishing. Preserve observations and distinguish implementation defects, violated test assumptions and unresolved questions. Record genuine design gaps without rewriting requirements.

## Deliver

Finish when required functionality is integrated, checks addressing important implementation risks are complete, and code, DESIGN.md and operating instructions agree. For unresolved issues, state the evidence, affected requirements and next useful check. Remove obsolete implementation plans and report actual checks and limitations.

There is no fixed generation deadline. Continue while work resolves a concrete delivery question; further imaginable scenarios alone do not require another investigation. If you cannot complete the task, explain why, identify unmet requirements and deliver the available result for independent audit. Provide ordinary startup and usage commands so the delivered programs can run without Codex or MCP.
