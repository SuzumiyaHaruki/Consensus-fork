# 系统要求

将 [protocol.md](protocol.md) 中的协议实现为可运行的 Go 复制KV系统。本文定义服务能力、工程成本与交付目标。实现端自行设计满足这些要求的架构、数据结构、并发机制和接口。

## 1. 服务与配置

交付模块 `example.com/mixepaxos`，包括可复用共识 Node、独立服务进程、真实网络传输、客户端库与 CLI，以及测试和文档。支持多个独立并发客户端。配置成员名单、各副本地址及 f/s/W/e/K，n 由成员名单确定；参数须满足 protocol.md 的约束。

通过共识实现确定性的单键 Put、Get、Delete。明确这些操作的输入、执行效果、返回值及错误含义，并据此定义命令冲突关系。格式错误及已知矛盾 rid 复用在接纳前拒绝，不能让合法命令依赖被拒绝的输入。客户端会话身份必须唯一，RequestSeq 并发分配不重复，具体分配与编码方式由实现选择。

## 2. 客户端结果与重试

首次执行向等待该请求的客户端提供实际应用结果。已执行的重复请求返回 ALREADY_EXECUTED，表示该请求已经执行，本次回复不包含原来的执行结果。

区分接纳前拒绝、尚未完成、实际应用结果、ALREADY_EXECUTED 和结果未知，具体状态码和接口表示由实现选择。同一入口收到尚未执行的重复请求时，复用已有工作，不重复创建实例；具体等待和回复方式由实现决定，尚未执行时不能返回 ALREADY_EXECUTED。

客户端超时或停止等待后，已经接纳的请求仍按协议继续处理。是否提供主动取消等待的接口，以及是否允许撤销尚未接纳的排队请求，由实现决定。换入口重试保留原 rid 和完整命令。客户端等待和退避策略由实现选择。客户端重启时若丢失原身份与请求记录，取得新身份开始新操作；不要求实现客户端持久重启日志。

通过执行记录判断请求是否完成，不能从结果缓存是否存在作判断。已经准备交付的原结果回复继续正常交付。入口本地不知道的 rid 可以正常接纳；跨入口重试可以对应不同实例，但状态机执行须按 rid 去重。

## 3. 真实运行时与可测试性

Node 启动后使用真实时间自主推进。支持多个副本同时接收客户端请求，并在每个副本内同时推进多个共识实例，处理协议消息、定时器和应用执行。在遵守依赖顺序、原子性和准入限制的前提下，某个实例等待网络回复或缺失数据时，其他可推进的实例和后台任务应继续处理。传输可替换，共识组件可在不使用 socket 的情况下运行。

自行选择队列、线程、锁、任务生命周期、重试、缓存及证据获取机制，同时保持协议要求的原子转换、当前权限检查与公平进度。支持关闭节点和过载时限制新请求；说明这些操作如何处理尚未接纳和已经接纳的请求。

在明确的可信集群边界内，将配置成员身份与实际消息来源关联，编解码保留身份和载荷；不能只信任未经核对的消息内成员字段。解释实际计时和发送机制如何对应 protocol.md 的窗口及心跳前提；本地队列入队或函数返回的名称本身不建立这些前提。说明运行条件及可检测的局部违例，不把它们当作全局窗口证明。

提供时间、消息交付和相关运行时事件的控制与观察接口，并给出通过真实 Node 或服务入口执行的可运行示例。受控与普通运行使用同一协议实现；说明示例经过哪些真实路径、替换或绕过哪些机制。不要求控制每个 goroutine。

## 4. 性能与资源使用

按 protocol.md 实现冲突查询、依赖展开和数据保留。普通冲突查询使用合适的索引，避免每次扫描全部历史；复用已有数据和已完成的检查，减少重复传输与重复任务，及时释放不再需要的临时状态。控制排队和并发工作量，同时保证后台任务继续推进。

提供实际测量，说明请求并发度增加时的吞吐、延迟和资源占用表现；负载和测试方法由实现端选择。

说明普通请求、依赖展开和缺失数据获取的时间、通信及内存开销如何随历史规模变化，以及资源限制对已接纳请求的影响。crash-stop 模型允许存活副本在内存中保存数据，不要求通过磁盘支持崩溃后重启。

## 5. 交付

优先使用标准库，支持离线构建。默认使用回环地址。提供普通命令即可启动的服务端和客户端。自动化测试放在 `tests/`，可用 `go test ./...` 运行。

README 包含配置、接口、服务语义、运行条件及本地多进程集群的构建、启动、使用和清理命令。给出七成员参数示例、并发客户端和同请求重试的用法，展示应用结果与重复、未知状态的区别。

`DESIGN.md` 说明交付实现的架构、状态归属、重要接口和影响行为的选择，包括计时、冲突索引、依赖展开、数据获取与保留。报告实际检查、未满足要求和已知限制；记录限制不能取消给定要求。
