# 实现提供的共识系统

完整阅读 protocol.md 和 system.md，实现其中要求的完整系统。按 IMPLEMENTATION.md 的工作要求，交付可运行程序、可复用组件、测试和文档，不能只交付实现计划或共识代码包。

## 构建与调查

先在 DESIGN.md 中简要说明准备采用的实现方案，再随着代码逐步完善。每一步都尽量形成可以运行的结果：先让一个请求从客户端进入系统，经过副本通信、决定和应用执行，最终返回结果；再逐步实现所需的并发、故障处理和生命周期行为。这个实现顺序不减少最终要交付的功能。添加功能时检查组件之间的交互，交付前审阅代码组织。

优先调查已经出现的失败和尚未解释的运行异常，不要只增加相似的通过测试或润色报告。保留实际观察，判断问题来自实现、测试条件不符合假设，还是目前尚无法确定。发现设计材料缺少必要说明时，应记录具体问题，不自行改写要求。

## 交付

当所需功能已经集成，针对重要实现风险的检查已经完成，且代码、DESIGN.md 与运行说明一致时，可以结束。对尚未解决的问题，说明已有证据、影响哪些要求，以及下一步可以怎样检查。删除过时的实现计划，报告实际检查结果与局限。

生成阶段没有固定截止时间。继续工作应当用于解决具体的交付问题，不必因为还能设想更多测试场景就一直调查。若确实无法完成，说明原因和未完成的要求，将现有结果交付独立审计。提供普通的启动和使用命令，使交付程序可以在不依赖 Codex 或 MCP 的情况下运行。
