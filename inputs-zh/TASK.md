# 实现给定的共识系统

实现 `protocol.md` 和 `system.md` 描述的完整系统。完整阅读两份文档。按要求交付可运行程序、可复用组件、测试和文档；仅交付代码库接口或计划不够。实现和证据工作遵循 `AGENTS.md`。

先在 `DESIGN.md` 中写一个简短草图，再随代码一起更新。以小步、可运行的增量构建系统：先让一个正常请求从客户端经过副本通信、决定和应用执行，最终得到回复；再在同一实现上扩展材料要求的并发、故障处理和生命周期行为。这个实现顺序不缩减最终范围。添加行为时检查组件交互，并在交付前审阅代码组织。

根据设计风险选择测试。优先处理已经观察到的失败和未解释的运行时异常，而不是增加更多相似的通过案例或润色报告。保留失败输入和观察，尝试复现并缩小原因范围；后续通过本身不能解释此前失败。区分已证实缺陷、测试前提被违反的证据，以及尚未解决的观察；对未解决事项指出下一项有用检查。测试位置和报告遵循 `AGENTS.md`。记录真实规格缺口，不改写要求。

按 `system.md` 完成交付物和运行说明。报告实际检查、失败和限制。使 `DESIGN.md` 与交付代码一致，删除过时计划；指出未满足的要求，不重新定义要求。

生成阶段不设固定截止时间。依据实现和证据判断何时交付，而不是依据耗时或测试数量。当所要求的功能已集成、与所选设计风险相称的检查已覆盖重要路径，并且代码、设计和运行说明一致时，结束生成。处理已经证实且妨碍必需行为的缺陷；对未解释的失败调查到足以说明已知事实和剩余不确定性。继续工作应当用于解决具体交付问题，或影响对必需行为判断的疑问。仅仅还存在其他可能的场景，不构成必须继续调查的理由。为独立审计者记录未解决观察和后续有用检查。若真实阻碍使任务无法完成，说明阻碍和未完成要求，然后结束会话。完成委派工作并交付最终结果；不要试图在交接前穷尽独立审计。

TCP 或多进程检查使用 `forge_local.isolated_exec`。工具说明介绍了私有网络、进程生命周期、保留记录和可选源码副本。这些是测试环境设施；交付的服务端和客户端也必须能通过普通文档命令运行，不依赖 Codex 或 MCP。每次隔离执行有命令超时，这不构成生成阶段的截止时间。

可选的适配器调度和重放工具位于 `../inputs/schedule.py`，使用 `python3 -I PATH --help` 查看帮助。在 `forge_local.isolated_exec` 内运行调度；选择捕获的源码副本时使用工具绝对路径，并把有用的适配器和计划源文件保留在 `tests/`。工具按计划调用适配器，并记录请求和实际返回的观察。可控制的范围取决于适配器暴露的事件；这些控制之外的线程调度仍由运行时和操作系统决定。结合适配器、实际运行路径和测试断言，判断是否符合给定假设、场景是否可达，以及共识性质是否满足。输入和注入故障须符合给定假设。是否使用该工具由你选择。
