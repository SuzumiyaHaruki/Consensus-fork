# 修复提供的候选实现

遵循 IMPLEMENTATION.md 和给定设计。阅读 .forge/feedback/handoff.json、其中的 issues_file，以及相关原始报告与复现。overview 帮助你定位问题和证据，其中的摘要不能代替核查。只处理 handoff.repair_issue_ids 指定的问题，并对每项给出一次处理结论；旧交接没有该字段时，使用 issues_file 中全部 ID。其他待处理问题作为背景。

## 理解证据

逐项核对审计者引用的要求，检查触发条件是否允许、能否实际出现、原因是否成立，以及是否还有其他解释。涉及耗时的结论，要说明时间假设约束了哪些实际事件。核对性能问题的测量条件、原因和实际影响，不能仅因材料没有给出数值指标就否定问题。可行时先运行原始复现，再修改代码。阅读断言和 polarity 字段，弄清测试通过或失败的含义：PASS 可能表示成功复现了缺陷。保留原证据，解释 API、路径适配并重新构建临时二进制。测试无法编译，或无法再构造原来的触发场景，都不能说明问题已修复。

索引中的路径以 .forge/feedback/ 为起点；原始记录中的路径仍以其所属运行目录为起点。execution_records 定位命令与结果：restore 将工作区目标映射到保留输入，outputs 列出保存文件，cwd_relative 表示源码相对工作目录。复用前检查替换实现的 overlay。history_file 包含已关闭问题和复核新增证据，关闭结论只对应记录版本。evidence_index_file 可能包含可复用案例、未决问题及未完成调查的 supplemental_turns。使用前先判断补充材料支持什么结论，不把未完成的草稿当成已经确认的发现或额外修复任务。

## 修复与影响检查

针对已经确认的根因修改代码，同时保持协议规定和系统要求的服务行为。自行选择修复方案，不必照搬审计者的建议。如果证据表明审计结论不成立，就说明理由，保留符合要求的实现。不要只为通过某个测试添加特殊分支、削弱断言或关闭要求实现的功能。

如果问题仅在于文档作出了无依据的性能声明，可以更正文档，并明确说明实现行为没有改变。如果证据表明实现本身存在性能问题，不能仅通过删除声明或添加使用限制，就宣称问题已修复。修复仍须满足给定的协议与系统要求。

检查代码差异，明确哪些机制发生了变化。核对这些变化是否影响原有的处理条件、协议规定的消息发送与处理，以及后续流程，尤其是原先能成功、现在可能被拒绝、延迟或重复处理的操作。选择能检查原问题、相关行为和历史问题的测试，不要求每轮运行所有旧测试。区分协议偏离、正确性错误和性能变化，必要时在可比条件下比较成本。说明断言能支持什么、哪些内容未检查；原反例消失或请求最终成功并不足够。更新 DESIGN.md，使其符合代码。

证据反驳发现时使用 not_substantiated，调查不完整时使用 unresolved；只有要求缺失或矛盾导致无法确定合规修复时，使用 needs_specification。指出具体缺失或矛盾的规则，以及哪些问题 ID 的修复依赖它；材料未规定的实现机制自行选择，继续处理不受该缺口影响的问题。不改写设计。代码未改也需接受独立复核。

## 执行与交付

按 IMPLEMENTATION.md 使用 forge_local.isolated_exec。默认在 work 中测试正在修改的实现；source="candidate" 选择本轮修复前的候选版本。引用实际执行记录，解释被测版本，保留前后观察。文件缺失或适配器损坏属于复现限制。用证据、解释或更窄结论回应 evidence_feedback，不因此强制新增测试。

当每项分配的问题都有基于证据的处理结论，能够完成的修复和相关回归检查已经完成，且 DESIGN.md 与交付代码一致时，可以结束。修复已经确认由本次改动引入的问题。修复没有固定截止时间：围绕具体修复疑问继续，随后将未决事项和有用检查交付独立复核，不扩展成无限的全系统审计。交付前结束或停止子智能体的工作，保留完整的反馈材料；测试代码放在 tests/。

写入 .forge/repair-result.json，包含 input_commit、action（候选文件变化时为 repaired，否则 no_change）、说明性的 summary 和 issues。每项需要 id、disposition（addressed、not_substantiated、unresolved、needs_specification）及 reason。Summary/reason 可用非空文本、列表或对象；控制字段为字符串。解释围绕**要求与原因、改动或不改的理由、前后证据、受影响行为与剩余问题**组织。合并共同解释并引用证据，不要求额外报告或固定子字段。这些是修复声明，不是关闭决定。最终说明实际改动、命令与结果及局限。
