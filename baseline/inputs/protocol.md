# Mixed-synchrony EPaxos-style protocol

This document specifies the protocol for this run. `pseudocode.md` expands its events, records and validation rules; both are supplied to generation, audit, repair and review. The pseudocode describes the algorithm, not a required package layout or runtime architecture. Read them together. Report a substantive contradiction rather than silently choosing the easier rule or substituting another protocol. Correctness arguments below state premises and limits; they are not reports of executed tests.

## 1. Model and parameters

The fixed member set is Pi, with n members and a common ordering of member IDs. At most f members crash during the entire run, with 0 <= f < n. A crash permanently stops the replica; it never resumes or rejoins. A correct replica never crashes in that run; a replica alive now may crash later. Start from a clean configuration with no external old state. Messages are not forged or altered. Reordering and duplication are allowed; FIFO transport is not assumed. Communication, request handling and task scheduling between correct replicas are reliable and fair. A continuously alive slow replica eventually processes requests. Only finitely many events occur in a finite real-time interval.

W > 0 is a complete broadcast-RPC window measured from the start of that broadcast. It includes sending to all members, transmission in both directions, recipient processing, required evidence retrieval and clock error. For a collector that remains alive, completes the broadcast to all members and actually waits to the window deadline, at most s members still alive at that deadline have not had their responses received by the collector. The slow members may differ between collectors and windows. This constrains responses actually received by the collector, not just requests received by peers. It does not give a separate delivery deadline for every message or accurate evidence that an unresponsive member has crashed. Do not claim this premise holds when its sending, processing or survival conditions do not hold.

The window model is an external assumption about actual payload and work. Fairness alone does not imply W. The Omega construction additionally assumes bounded local clock drift and at least one correct heartbeat source whose broadcast intervals are eventually bounded. Queueing, encoding, validation and scheduling mechanisms remain implementation choices, but their costs cannot be removed from these premises by renaming events.

| Parameter | Meaning and constraint |
| --- | --- |
| q = n - f | Minimum eventual response threshold; 0 <= s < q. |
| L = f + 1 | Early Collect threshold; this protocol uses q <= L, and L + q = n + 1. |
| e | Integer missing-fast-vote budget, e >= 0 and 2e < q; not the actual crash count. |
| F = n - e | Matching initial-vote threshold for fast decision, including the origin. |
| K | Fixed private admission slots per origin, integer K >= 1. |

For example, n=7, f=4, s=2, e=1 gives q=3, L=5 and F=6. Five responses can complete a Collect early; they do not authorize fast decision. These relations belong to this protocol, not every EPaxos variant.

## 2. Identity, values and retained state

An admitted instance x has ID `(origin, localCounter)`; an origin never reuses its instance counter. A client command is `{rid, payload}`. The request ID rid identifies one logical operation and binds one immutable payload across retries; it is not the instance ID. One logical request may be admitted as different instances at different origins. A full value is `V = (cmd, D, seq)`; equality compares all three components. D contains other real admitted instance IDs, never x itself, with authentic complete initial descriptors that can be obtained. The unique initial descriptor `V0(x) = (cmd_x, D0(x), seq0(x))` is immutable. Define `S(D) = max({0} union {seq0(z): z in D})`.

Ballot 0 belongs to the origin. Positive ballots are ordered pairs `(round, coordinator)` in lexicographic order, all above 0. Local promises are monotone. An attempt identifies one Collect call, not a ballot; a new call uses a new attempt. Each stage has a nonce; stage 2 uses a fresh nonce, while same-stage retransmission keeps its key and payload.

Each replica retains descriptors, its immutable first PreAccept scan and vote, promise, accepted records with complete value/Cover/Selection and their history, immutable decisions with certificates, execution markers and application results. Its local cross-instance registry includes executed instances. The registry is not a globally synchronized table. This protocol does not retire executed instances from future conflict scans or perform logical garbage collection. Correct holders continue serving their records; crash-stop does not require a WAL for restarting crashed replicas.

Each replica has at most one active local coordinator task per instance. Tasks retain ballot, attempt/stage, Prepare outcome, evidence, missing conflicts and any frozen proposal. Freezing fixes one full proposal for this ballot; it is not decision. Late observations and HELP cannot modify it. Stopping a task cancels future coordination, without rolling back promises, votes, accepts, decisions or already issued messages. Preserve initial votes, NoFast and forced dependencies across task replacement. The origin's `seenMismatch[x]` is monotone: processing a valid initial Mismatch before decision closes its future fast path, even if that reply cannot enter the current Collect.

Cover explains why a value covers conflicts; Selection explains why this ballot may choose it. Both contain expandable evidence, not unchecked labels. Record references identify actual authors and unique local records, and form finite acyclic graphs pointing to earlier records. Dependency graphs may contain cycles; they are different from evidence-reference graphs.

## 3. Collect

`Collect(Op, payload)` keeps one operation and payload throughout the call. Requests and replies bind requester, actual sender, instance, ballot, attempt, operation, phase, nonce and relevant descriptor/value. Count distinct members, while retaining actual records from both stages. PreAccept Mismatch is a positive observation, not a NACK. NACK means rejection.

1. Start W when broadcasting phase 1 to all members, including self. A broadcast comprises individual sends and can be interrupted by a crash. Mark full sending only after the whole set has actually been sent under the declared transport semantics. After full sending, at least L responses permit early completion without waiting for W.
2. Otherwise, both W must have elapsed and at least q responses must have arrived before freezing the first-phase map A at the cut. If W expires with fewer than q responses, keep waiting; do not freeze a smaller A.
3. After the cut, broadcast the same operation and payload with a new nonce. B contains actual replies to this phase-2 request. After full second sending, finish when `|B| >= q` or `|A union B| >= L`. No extra W wait is required in phase 2. Count a member once, but keep both of its snapshots.
4. Successful operation evidence contains only positive replies. Never discard an admitted NACK to select a positive subset. A matching NACK may immediately fail a running attempt; saved state remains. A higher promise stops lower-ballot coordination; later eligible recovery starts a higher-ballot Prepare.
5. After the cut, late phase-1 replies cannot enlarge A or enter B. Same-key retransmission may return the original cached reply. A new nonce rechecks current promise; Prepare phase 2 rereads current accepted/decided state. Both phases' snapshots participate in highest-accepted selection.
6. Learn valid decision evidence independently of Collect completion. Process initial historical votes, including late Mismatch, independently too. A historical vote does not become a reply to a different call or phase. Missing evidence requires Fetch; it is not a positive response or explicit absence.

A successful Collect has at least q members. If either of two outputs has at least L members, L+q=n+1 gives intersection. If both outputs are smaller than L, the later cut's phase-2 responders intersect the earlier cut's phase-1 set in at least q-s members under the window premises. An intersecting replica need not be permanently correct, and replies are snapshots at actual production events rather than one simultaneous global state. The source's argument for two small outputs uses the earlier frozen set and its at-most-s omission among replicas still alive at the later cut, together with the later call's at-least-q second-phase responders. These counts do not replace actual phase records, promises or response checks.

## 4. Admission and the origin's paths

Clients enter an origin's fair FIFO queue. A queued request has no instance or descriptor and is not conflict-visible. With a free slot, admission atomically occupies it, allocates x, scans registered conflicts for D0(x), sets `seq0(x)=1+S(D0(x))`, saves V0(x), registers x and creates the origin's first scan and FastOK vote. Network sends need not stay inside that local atomic operation.

The origin launches one Collect(PreAccept). A recipient validates and installs the descriptor. If decided, it returns the decision; if its promise exceeds 0, it rejects new PreAccept processing. Otherwise its first PreAccept scan atomically observes registered conflicts, unions D0(x), and sets `seq_p=max(seq0(x),1+S(D_p))`. Save an immutable FastOK vote exactly when the complete observed value equals V0(x), otherwise a Mismatch. Repeated PreAccept does not rewrite the first scan or mint a different vote. A fully known descriptor becomes conflict-visible even when obtained through another evidence path.

Fast decision requires an active, undecided origin task at ballot 0, no known higher promise/ballot, seenMismatch=false and F distinct actual FastOK votes for V0(x), including the origin if counted. Any frozen proposal must equal V0(x). Atomically create the origin's actual decision record and FastCert, install the decision and schedule dissemination. Bare historical votes are not that decision record; a successor cannot manufacture it. The stated one-round-trip fast path starts after admission at PreAccept broadcast, excluding client queueing and execution.

The initial observation Collect may finish early, but normal Accept still waits until the first W deadline. Keep that timer and the initial-vote listener after early completion. If W expires before observation Collect finishes, continue that same call. With its successful proof, merge D0 and included first observations, and take the maximum suggested sequence, equivalently the merge formula in `pseudocode.md`. Freeze DirectCover and NORMAL Selection, then launch a distinct Collect(Accept). Observation replies are not AcceptACKs, and Accept is not observation Collect's phase 2.

If the normal value differs from V0, an included Mismatch must already have set seenMismatch. This ballot-0 selection does not require NoFast and does not enter recovery merely because a scan mismatches. A late Mismatch outside the frozen observation set can close fast decision without changing the normal merged value. Same-value Accept may overlap the fast path; fast decision stops further coordination without undoing saved accepts. Fast decision and freezing an unequal normal proposal must be locally mutually exclusive.

## 5. Recovery and permitted values

NeedRecover is a progress notification, not a death fact or selection authority. A replica starts positive-ballot coordination only while local Omega selects itself. Temporary disagreement about Omega is allowed; ballots, promises and evidence provide safety. Losing eligibility stops local positive-ballot tasks, but not request handling and evidence service. An Omega change does not stop normal ballot-0 origins.

Recovery chooses a ballot above known ballots, local promise and previously issued rounds, then runs Collect(Prepare). New Prepare, Observe and Validate requests raise promise before creating snapshots/scans. Fetch missing material outside atomic regions, then reenter and recheck current state. Explicit NONE means no initial vote was produced; an unavailable reference is not NONE. Use every actual Prepare snapshot from both phases, with this priority:

1. Learn valid existing decisions whenever encountered, without waiting for candidate selection.
2. If any accepted value exists, inherit the complete value and its original Cover from the highest accepted ballot. Bind Selection to this Prepare proof. Equal highest ballots must have equal values; disagreement is a violation, not an arbitrary tie-break. Forced dependencies and NoFast cannot override inheritance.
3. With no accepted value, let R be the member union, r=|R|, and H the distinct authors of matching initial FastOK votes in either phase, h=|H|. Existing valid NoFast, or `h < r-e` producing NoFast, permits Rebuild.
4. Otherwise `h >= r-e >= q-e > e`. Validate exact V0(x); do not silently merge new conflicts into it.

NoFast(x) permanently excludes an initial fast decision using at least e+1 distinct witnesses: an actual initial Mismatch for x; a positive-ballot Prepare snapshot explicitly reporting no initial vote; a FastOK vote for an initially mutually missing conflicting instance; or an eligible scan from the original Cover of an already decided conflicting instance. `pseudocode.md` defines their bindings and preconditions. Timeout, NACK, incomplete evidence or a local seenMismatch flag cannot replace this proof.

Rebuild requires a successful no-accepted Prepare, valid NoFast and no frozen proposal. Run Collect(Observe), with fresh conflict scans in each new phase. At freezing, union initial dependencies, all included observations and the current valid forced dependencies. Set seq to the maximum of initial seq, scan suggestions and `1+S(D)`. Keep the original command. DirectCover retains actual scans and force evidence; REBUILD Selection retains Prepare and NoFast. HELP during Observe does not restart it or change its request payload; freezing snapshots the latest applicable forced set.

Validate runs Collect(Validate), keeping fresh scans from both phases. Freeze `M = union(scanned dependencies) - D0(x)`. Each missing y is resolved only by y's authentic initial descriptor containing x or y's legal decided value containing x. Otherwise use HELP and Fetch. PENDING or an intention to add an edge is insufficient. With every missing conflict resolved and the task still eligible, freeze V0(x) with ValidatedCover and VALIDATE_INITIAL Selection. If NoFast arrives first, stop the old Validate flow and Rebuild using the successful Prepare; stale callbacks cannot subsequently freeze V0(x).

## 6. HELP, acceptance and evidence

HELP binds source instance, source ballot/task, target instance, both descriptors and actual initial support. Helping y while validating x requires a conflict, `y not in D0(x)` and more than e distinct FastOK votes for x. Send to current Omega and broadcast NeedRecover(y), retrying fairly. If y has a decision or `x in D0(y)`, return that evidence first.

Otherwise x and y initially miss each other. The votes for x produce NoFast(y). Save this fact and a forced dependency on x for a permitted rebuild of y. The target must still run or reuse its own Prepare; highest-accepted inheritance has priority and frozen values cannot change. More than e FastOK votes for y can also produce NoFast(x); returning these votes does not discard the obligation for y. HELP has no separate quorum and no Nop. Mutual HELP may legitimately produce an SCC.

If decided y lacks x, follow its original Cover through exact inheritance. A validated cover may contain an already produced decision certificate for x; learn it. Otherwise eligible scans omitting x can provide e+1 NoFast(x) witnesses. Dependency, scan and decided-instance bindings must match; do not use another resolution entry. Missing objects suspend this work. A decided-conflict force may add y in a rebuild of x using its actual NoFast and decision evidence. Circular evidence cannot assume a future decision.

Before AcceptACK, obtain, verify and save the complete proposal, Cover, Selection and reachable evidence. Atomically recheck current decision, promise and same-ballot value consistency. Accept the proposed full value without recomputing local dependencies. A successful positive Collect(Accept) produces AcceptCert and Learn. A valid completed Accept proof remains valid if its coordinator task has since changed. Higher-promise failure requires a new eligible Prepare, not recycled acknowledgments.

Use one decision installation operation for fast and accepted certificates. A second legal certificate must agree on the full value. First installation records the decision, stops coordination, removes recovery work and schedules dissemination/execution. Duplicate Learn must not cause endless immediate rebroadcast or repeated slot release. Retain promises, votes, accepted history and Cover sources. Serve Fetch and recovery/help queries even before local execution completes.

Normal message envelopes carry the needed complete objects, including descriptors and initial votes/scans, so reference fields alone do not add fetch round trips to the fast path. Physical sharing and references are allowed; incomplete receivers Fetch before using evidence. Successful acceptance retains at least one ultimately correct holder under Collect's premises. Availability does not replace highest-accepted inheritance. If an origin's FastCert disappears when it crashes, recovery preserves its value and forms a new AcceptCert rather than fabricating an origin decision from bare votes.

## 7. Execution, slots and clients

Fetch the full transitive decided dependency closure before executing a root. Missing descriptors trigger Fetch; undecided dependencies trigger recovery. Collapse the graph into SCCs, execute dependencies before dependants, and sort each SCC by `(final seq, instance ID)`. Preserve ordering across overlapping closures. Each instance gets one execution-completion transition.

Application state and the rid result table change in one deterministic transition. First execution applies the payload and retains `{rid,payload,result}`; later instances of that rid return the retained result without repeating the effect. Same-rid commands must conflict. Only actual execution permits an execution response; commit/admission is insufficient. Nonconflicting commands must commute in both final application state and each request's return value, including deduplication state. Equal final state alone is insufficient: two fetch-add operations returning old values conflict.

Only the origin's local execution completion, including deduplication, releases its instance's slot, once. Decision, timeout, retry, remote execution and remote notifications do not release it. A crashed origin's slots are not transferred. Slots limit only admission: Prepare, Observe, Validate, HELP, Accept, Learn, Fetch and execution continue fairly when all are occupied. Slot release does not remove executed instances from conflict scans or delete evidence.

Conforming clients use distinct request IDs for new logical operations and the same ID/payload across retries. Concurrent allocation cannot reuse an ID for a different operation. Encoding and retry scheduling are implementation choices. An entry merges queued/active duplicates and returns cached results for completed requests. Different entries may allocate distinct instances and slots for the same request; application deduplication prevents repeated effects. Reject known contradictory payload reuse without corrupting the original. Clients are not Byzantine; globally recovering from independently admitted contradictory payloads under one rid is outside this model.

If an entry stops, the client can retry the same request at other entries. Eventual client completion requires reaching a correct entry and continuing applicable waiting/retry behavior. Timeout/disconnection means an unknown result, not absence of execution, permission to change ID/payload or proof of death. Distinguish definite pre-admission rejection, application outcome and unknown result. No universal client completion deadline is given. A fresh operation, including a new read, uses a fresh rid. Client restart journals and durable external effects after replica restart are not prescribed.

Finite-closure reasoning assumes Agreement, eventual decisions for publicly available instances, retrievable descriptors and fair execution. An infinite reachable closure in a finitely branching graph would contain infinitely many distinct never-executed instances whose slots never release, contradicting finite nK slots. A finite closure can contain more than nK historical instances. Its size, client queueing and execution latency have no uniform bound. An instance lost before any correct holder can provide its descriptor is outside that instance's recovery guarantee; retry can create a new instance for the same logical request.

## 8. Omega and autonomous progress

Replicas repeatedly broadcast `HB(p,k)` with increasing positive k; receivers record the exact pair before ACK. Larger k does not imply earlier heartbeats were received. Observer check k sequentially waits `(k+1)*W` after the preceding check/scheduling point, then complains about other members whose exact kth heartbeat is absent. Waits accumulate quadratically; do not launch all checks from one initial time.

q distinct actual complaints about `(p,k)` form BadCert(p,k), not an accurate death certificate. Gossip fairly, deduplicate by `(p,k)` and count certificates per candidate. Local Omega selects minimum `(certificate count, member ID)`. Late heartbeats do not retract complaints/certificates. Duplicate certificates do not cause immediate broadcast loops. Omega changes stop ineligible positive-ballot tasks and wake recovery/help; normal ballot-0 origins remain eligible.

The source's stability argument uses section 1's extra assumptions: one correct source's broadcast times eventually grow at most linearly while checks grow quadratically; eventually fewer than q correct observers can complain about its particular heartbeat. Crashed sources accumulate unbounded certificates. This is the proposed argument, not independent verification of the complete recovery system.

Keep idempotent work for every known undecided instance. Missing descriptions trigger Fetch; after finite grace, complete descriptions trigger NeedRecover and eligible recovery. Repeat running Collect requests with the same current-phase nonce, and retry HELP, Fetch and notifications fairly. Missing-object replies do not prove absence or remove work. Received objects wake deferred handlers, which recheck task/ballot/stage before proceeding, and wake validation/execution. Descriptors, votes, accepts and dependency references can all create recovery work. Waiting does not block other instances. Grace and retry intervals control scheduling, not failure detection.

## 9. Targets and limits

Safety targets are Agreement on an instance's full value and conflict Visibility: two conflicting decided instances have at least one final dependency edge between them. Assuming these properties, complete finite closures, deterministic execution, return-value-aware conflicts and request deduplication, the source gives a conditional argument for linearizable client histories. Execution-before-response alone does not prove that result. Audit these targets under their premises and distinguish source-design counterexamples from code deviations.

Highest-accepted induction, Cover inheritance and atomic conflict registration give the stated reasoning structure. Complete evidence-validity induction, all HELP/concurrent-ballot combinations, Omega with recovery termination and unbounded implementation refinement remain unproved in the source. Historical finite graph/interleaving counts do not validate this revision. These limits do not authorize weaker quorums, skipped certificate checks, accurate-death substitutes for Omega or disabled retries.

Fixed W must cover actual work, but history and evidence bytes have no uniform bound. K does not solve growth. Measure and explain experimental operating conditions; an arbitrary history cap or discarded required dependencies/evidence is not authorized. Stronger environment premises, new reclamation/chunking protocols or weaker service guarantees are protocol/scope revisions, not implementation-only choices. Snapshot installation, safe history deletion, dynamic membership, crash-restart and arbitrary partitions are outside this design.

## 10. Scope of this experiment

For each cluster run starting from clean state, limit the workload to at most 10,000 new logical requests in total across all clients, counted by distinct rid. Retries with the same rid do not consume another logical-request allowance, although they may create additional instances; record logical requests, retries and admitted instances separately. This is a workload ceiling, not a required test size or a limit on the total number of tests. At the ceiling, stop issuing new logical requests and continue retries, recovery and execution for outstanding work within the available execution budget; report unfinished work if that budget expires. Enforce this ceiling in the workload driver, not by hard-coding a server rejection threshold, dropping admitted work or deleting required history. Choose and explain a fixed W for each cluster run and observe whether its actual workload satisfies the W/s premises; the request ceiling does not itself establish them. Long-term unbounded service and reclamation are outside this experiment's evaluation scope.
